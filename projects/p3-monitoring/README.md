# Модуль 3. Мониторинг сайтов

- Репозиторий проекта: https://github.com/shargabong/monitoring
- Сайт: https://shargabong.github.io/monitoring/

## Что получилось

Разработан веб-сервис для отслеживания доступности сайтов и просмотра истории предыдущих проверок. Вся информация сохраняется в JSON-файлах прямо в репозитории. Фронтенд написан на React с использованием Vite и размещён на GitHub Pages.

Сейчас в мониторинг добавлены GitHub, MDN Web Docs, Node.js, Vite и Википедия. Список URL хранится в public/data/sites.json, поэтому его легко редактировать без правки кода страниц.

## Выполненные требования

- На главной странице отображается общая сводка: название, ссылка и итог последней проверки для каждого ресурса (время отклика или описание ошибки, если данные уже собраны).
- У каждого сайта есть отдельная страница со списком прошлых проверок, где указаны дата, статус и скорость ответа либо ошибка.
- Добавлен раздел «О проверке» с описанием принципа сбора данных и периодичности запусков.
- При переходе по несуществующему адресу открывается страница с кнопкой возврата на главную.
- Поддерживается переход по прямым ссылкам и обновление любых внутренних страниц — маршрутизация работает через хэш (#), благодаря чему GitHub Pages корректно отдаёт приложение.
- Настроен воркфлоу в GitHub Actions для ежедневных ночных проверок, при необходимости его можно запустить вручную во вкладке Actions.
- Итоги проверок записываются в public/data/results.json, после чего проект автоматически пересобирается и деплоится заново.
- Telegram-бот присылает уведомление, если ресурс упал или восстановил работу. Если статус не менялся или это самый первый запуск, сообщения не отправляются.

## Как работает проверка

Скрипт scripts/check.mjs поочерёдно опрашивает адреса из списка с таймаутом 15 секунд на каждый. Успешными считаются HTTP-коды 200–299. В отчёт фиксируются время запуска, код статуса, длительность запроса и текст ошибки (если она была).

В файле результатов хранятся 30 последних запусков, отсортированных от новых к старым. При очередном прогоне скрипт сверяет текущий статус каждого сайта с предыдущим и при смене состояния отправляет оповещение в Telegram. Токен бота и ID чата вынесены в секреты репозитория и не попадают в кодовую базу.

Запуск в GitHub Actions запланирован на 21:00 UTC (00:00 по Москве), однако сам GitHub может запускать задачу с небольшой задержкой. После обновления JSON-файла отдельная джоба выполняет сборку и обновляет сайт.

## Дополнительно

- Лог проверок ограничен 30 последними записями, чтобы файл не разрастался бесконечно.
- В карточке и истории видно время ответа, а при ошибке код или сообщение об ошибке.
- Есть уведомления и о недоступности, и о восстановлении сайта.
- На сайте предусмотрено сообщение об ошибке, если файлы с данными не загрузились.

## Локальный запуск

Нужен Node.js. После клонирования репозитория выполнить:

```sh
npm install
node scripts/check.mjs
npm run dev
```

Адрес для открытия покажет Vite. Локальная проверка обновит файл результатов. Для отправки сообщений дополнительно нужны переменные окружения `TELEGRAM_TOKEN` и `TELEGRAM_CHAT_ID`. Если их нет, проверка сайтов всё равно выполнится, но сообщение отправлено не будет.

Для проверки сборки и кода:

```sh
npm run build
npm run lint
node --test scripts/notify.test.mjs
```

Тест проверяет, что уведомления выбираются при изменении доступности, а одинаковые результаты и первая проверка не считаются изменением.
